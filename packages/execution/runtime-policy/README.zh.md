# `@deepseek-ai/dsh-runtime-policy`

`runtime-policy` 负责 Harness 2.0 的执行冻结边界，位于 Core Agent Loop 外层。Core 只暴露一个内部 `agent/step-snapshot` 瀑布扩展点；本包把执行域事实写成持久 Session 事件，再把这些事件的序号引用交回规范 `step/snapshot`，不另建第二套持久化通道。

## 合同

- **能力权限**：以“能力 + 规范资源”表达 `allow / ask / deny`。同一来源内由更具体规则细化，不同来源之间只能继续收紧，因此配置或委派不能反向放宽沙箱边界。
- **全局预算**：统一记录令牌、微单位成本、墙钟时间、工具调用、Agent 启动和风险点。执行前扣账用于准入控制；真实发生后的观测消耗即使越过上限也必须记账，不能把超额消耗从账本中抹掉。
- **执行世界**：冻结当前工作区策略和实际挂载的执行能力。
- **世界副作用回执**：可能改变外部状态的工具在真正执行前先写 `world/effect-start`，结束后写匹配回执。崩溃后只有 start、没有 receipt 的操作明确处于“结果未知”，不能默认安全重放。
- **Agent 类型 / 已解析配置**：冻结当前 Agent 粗粒度角色以及本次尝试使用的非消息模型与运行参数。

本包为 `StepSnapshotRefs` 扩展 `permission / budget / world / config` 四个引用；可选 `./invariant` 伴生包负责校验这些引用以及副作用 start/receipt 关系。规范事实只存在于 Session 事件中，Cordis 事件仅用于进程内协作。

## 模型体验

### 运行时策略边界

#### 模型看到什么

本包不会直接增加提示词、消息、工具结构或模型请求。模型只会看到执行准入之后产生的后续工具结果。

#### 令牌影响

本包不直接增加提示令牌；持久化运行时策略事件对模型隐藏。

#### KV Cache 影响

不会直接使请求前缀失效；执行策略变化可能改变后续工具结果，因此只影响之后的对话内容。
