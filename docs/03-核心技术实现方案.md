# 03 核心技术实现方案

## 1. 技术选型原则

技术栈围绕四个目标选择：

1. 本地优先，工程数据可长期保存。
2. 视觉 / AI 算法可以快速迭代。
3. 3D 编辑器具备实时交互能力。
4. 核心状态、任务调度和文件管理必须稳定。

因此采用“Rust 核心 + TypeScript 界面 + Python 算法 Worker”的组合，而不是让所有逻辑都堆在 Node 或 Python 中。

## 3. 图像导入

导入流程：

1. 计算内容 Hash。
2. 读取 EXIF。
3. 自动纠正方向。
4. 提取原始尺寸、焦距等信息。
5. 生成不可变 Original Asset。
6. 建立 Observation。
7. 生成低分辨率 Preview。
8. 将后续分析任务加入 DAG。

禁止后续算法直接修改原图。

---

## 4. 图像质量检测

需要自动检测：

- 模糊
- 过曝
- 欠曝
- 运动模糊
- 极端鱼眼
- 分辨率不足
- 大面积遮挡

输出不是简单“好 / 坏”，而是：

```json
{
  "sharpness": 0.81,
  "exposure": 0.92,
  "motion_blur": 0.07,
  "usable_for_geometry": true,
  "usable_for_texture": true
}
```

低质量照片仍可保留语义价值。

---

## 5. 图像特征与匹配

第一阶段可采用：

- SuperPoint / SIFT 作为特征
- LightGlue / LoFTR 类模型作为匹配

架构不绑定具体模型。

流程：

1. 对每张图生成 embedding。
2. 先做全局相似度筛选候选图片对。
3. 候选对再做局部特征匹配。
4. RANSAC 过滤错误匹配。
5. 建立 Image Match Graph。

避免 N 张图片全部两两暴力匹配。

---

## 6. 相机位姿与 SfM

优先使用成熟实现：

- COLMAP
- PyCOLMAP

实现：

1. 读取已确认匹配。
2. 恢复相机内参。
3. 计算相对位姿。
4. 增量式 / 全局式 SfM。
5. Bundle Adjustment。
6. 输出 Sparse Point Cloud。
7. 写入 Camera Candidate。

如果 SfM 无法把某张照片接入同一组件：

不要丢弃。

将其作为新的 Zone / Cluster 候选交给语义空间关系模块。

---

## 7. 视频处理

视频不是“每一帧都是照片”。

流程：

1. FFmpeg 解码。
2. 关键帧选择。
3. 去除重复 / 模糊帧。
4. 保留时间关系。
5. 估计连续位姿。
6. 与照片 Observation 合并。

可引入视觉里程计 / SLAM 插件。

视频连续性可作为高权重约束。

---

## 8. 深度估计

深度分两类：

### 几何深度

来自：

- MVS
- LiDAR
- 双目
- RGB-D

高可信。

### 单目估计深度

来自可替换 Depth Model。

它主要用于：

- 初始几何
- 平面关系
- 遮挡
- 相对深度

单目深度不得直接当绝对尺度。

需要通过：

- 已知物体尺寸
- 门高
- 相机高度
- GPS / LiDAR
- 多视图几何

进行尺度对齐。

---

## 9. 语义分割与对象跟踪

目标：

- 把同一实体在不同照片里的观测关联起来。

推荐：

- SAM 系列用于 mask
- 通用视觉 embedding 用于跨图检索
- 检测 / 开放词汇识别模型提供类别

Entity Association 使用组合分数：

```text
总分 =
视觉特征相似
+ 几何位置一致
+ 尺度一致
+ 材质 / 颜色一致
+ 语义一致
+ 时间连续性
```

不能只靠文本标签“chair”。

---

## 10. 平面与建筑结构

室内空间非常适合结构化约束。

识别：

- 地面
- 天花板
- 墙
- 门
- 窗
- 柱
- 楼梯

结合：

- 深度
- 法线
- 线段
- 消失点
- Manhattan World 假设

建立结构平面。

建筑结构应优先转为可编辑 Mesh，而不是永久使用 Splat。

---

## 11. 跳跃照片空间关联

当两张照片没有足够局部特征：

进入 Semantic Spatial Matcher。

证据包括：

- 相同固定家具
- 相同门窗
- 墙纸
- 地砖
- 柱
- 独特装饰
- 室外建筑边缘
- GPS
- EXIF
- 用户文字

输出多个候选 Transform / Topology。

禁止无证据直接强行求 6DoF 坐标。

---

## 12. Zone 聚类

照片首先根据：

- 几何连通
- 视觉匹配
- 空间语义
- 时间连续

形成 Observation Cluster。

Cluster 进一步解释为 Zone：

- room
- corridor
- floor
- outdoor
- building facade
- garden
- street

Zone 是逻辑空间，不等于渲染 Chunk。

---

## 13. Anchor

Anchor 是跨 Observation / Zone 对齐的重要稳定点。

类型：

- DOOR
- WINDOW
- STAIR
- CORNER
- FIXED_OBJECT
- FACADE_FEATURE
- GPS_POINT
- MANUAL

Anchor 具有：

- Local Pose
- Candidate World Pose
- Observation bindings
- Semantic signature
- Confidence

Anchor Resolver 负责匹配同一个 Anchor。

---

## 14. Portal

Portal 表示可通行或强连接的空间边界。

例如：

- 门
- 楼梯口
- 电梯
- 开放拱门
- 阳台门

Portal 有两个端点 Zone。

```text
living-room ← door-01 → garden
```

室内外关系优先通过 Portal 求解。

---

## 15. 因子图与约束求解

采用 **GTSAM 作为第一阶段求解器 + 自研约束抽象层**。自研部分负责把 888 的空间、语义和拓扑关系转换为统一 Constraint / Factor，不重复实现一套通用非线性求解器。

变量：

- Camera Pose
- Zone Pose
- Entity Pose
- Anchor Pose
- Scale
- Plane
- Gravity

Factor：

- Visual Reprojection
- Relative Pose
- Depth
- Plane
- Same Anchor
- Portal Connectivity
- GPS
- Known Size
- User Constraint

求解器输出：

- 最优状态
- 残差
- 协方差 / 不确定性

语义约束转换为数学 Factor 后再参与求解。

---

## 16. 多假设求解

对于离散歧义，不只使用一个连续优化问题。

例如室内位置可能有三种拓扑关系。

使用：

- Hypothesis Branch
- Branch Score
- Constraint Satisfaction
- Beam / Top-K 保留

每个 Branch 内部再运行连续优化。

后续证据通过似然与约束重新评分。

---

## 17. MVS / 密集重建

对于高重叠照片：

1. MVS 得到 Dense Point Cloud / Depth。
2. 深度一致性过滤。
3. 融合。
4. 生成：
   - TSDF
   - Mesh
   - Splat

推荐：

- COLMAP Dense / OpenMVS
- Open3D TSDF

算法实现通过插件接口替换。

---

## 18. Gaussian Splat

Splat 用于：

- 快速高保真场景
- 难网格化细节
- 植被
- 远景

可使用：

- gsplat
- Nerfstudio 相关实现

必须保存训练来源 Observation 列表。

Splat 不能成为 Canonical World State 本身，只是 GeometryRepresentation。

---

## 19. Mesh 重建

Mesh 来源：

- TSDF
- Poisson
- Provider
- Primitive Reconstruction
- 用户建模

处理流程：

- 去噪
- 修洞
- 重拓扑
- 简化
- UV
- Texture baking
- LOD
- Collider

Open3D / trimesh 处理基础几何。

复杂资产转换使用 Blender Headless。

---

## 20. 对象级 3D 生成

对象生成流程：

1. 找到所有 Observation mask。
2. 选最佳视角。
3. 尽可能组成多视图输入。
4. 去除背景。
5. 估计真实尺寸。
6. 调用 OBJECT_3D Provider。
7. 标准化坐标。
8. 尺寸对齐。
9. 材质修正。
10. 放回真实世界 Pose。
11. 从原相机位渲染验证。

Provider 可接：

- Hunyuan 类
- Meshy 类
- Tripo 类
- 本地模型

业务层不直接依赖品牌。

---

## 21. 场景级生成补全

用于完全缺失区域时：

输入必须包含：

- 相邻 Zone
- Portal
- 几何边界
- 风格
- 材质
- 已知尺寸
- 禁止修改部分

生成结果必须被标为 Generated。

优先生成“连接空间”，避免重新生成已有真实 Zone。

---

## 22. 材质恢复

材质处理：

1. 从多 Observation 选择无遮挡视角。
2. 光照归一化。
3. 纹理投影。
4. PBR 分解候选：
   - Base Color
   - Roughness
   - Metallic
   - Normal
5. 多视角融合。
6. 空缺区域 inpaint。

真实纹理与 AI 纹理必须记录来源区域。

---

## 23. 光照

第一版目标：

- 室内 / 室外主光方向
- 色温
- 强度
- 环境光
- HDRI 候选

不追求物理测量级反演。

验证时区分：

- 几何错误
- 光照错误

防止用错误光照掩盖错误几何。

---

## 24. 渲染验证

验证渲染必须使用：

- 原始 Camera Intrinsics
- 原始 / 优化 Camera Pose
- 同一分辨率或标准缩放

输出：

- RGB
- Depth
- Normal
- Entity ID
- Material ID
- Mask

便于逐项比较。

---

## 25. 自动误差定位

指标：

### 几何

- Reprojection Error
- Depth MAE
- Normal Error
- Silhouette IoU
- Chamfer Distance（有参考点云时）

### 视觉

- SSIM
- LPIPS
- Feature Similarity
- Color Histogram / Delta

### 语义

- Object Presence
- Object Count
- Relative Position
- Occlusion Order

最终不要输出一个总分就结束。

必须输出“哪里错、错的类型、建议怎么修”。

---

## 26. Repair Planner

规则优先级示例：

### 位置错、形状对

调整 Transform。

### 大小错

调整 Scale，重新验证。

### 相机错

优先修 Camera。

### 局部轮廓错

局部 Mesh Deform / Replace。

### 材质错

重投影 / 重新估计材质。

### 几何完全错误

重新调用 Reconstruction 或 Provider。

所有修复都形成 Task Graph，不直接同步阻塞 UI。

---

## 27. 下一最佳观测

Next Best View 计算：

```text
价值 =
预计减少的世界不确定性
× 区域重要性
÷ 用户拍摄成本
```

候选位置来源：

- 现有 Portal
- 未闭合 Zone
- 低可信 Anchor
- 遮挡区域
- 多假设分歧最大的区域

输出自然语言提示和可选 3D 箭头。

---

## 28. Provider Router

接口示例：

Provider 协议使用权威 Schema 定义，语义上至少包含：

```text
capabilities()
estimate(request)
execute(request, context) -> ArtifactCandidate
health()
```

**Provider Router 的选择策略与调度状态位于 Rust Core。** 远程 HTTP Provider 可由 Core Adapter 执行；依赖 PyTorch / 本地模型 / GPU 的 Provider 任务派发给 Python Worker 执行。无论执行位置在哪里，都只能返回 Candidate / Artifact，不能直接修改 Canonical World State。

Router 不只比较价格，还比较：

- 当前成功率
- 平均时延
- 目标质量
- 格式
- 输入限制
- 数据隐私
- 本地 / 远程

## 30. 跨平台与 GPU

### Windows

- CUDA（NVIDIA）
- DirectML 作为部分模型回退

### macOS

- Metal / MPS

### Linux

- CUDA / ROCm 视 Worker 能力

## 31. 第一版刻意不做

避免失控：

- 自研基础视觉大模型
- 自研完整 3D 生成基础模型
- 大规模多人在线协作
- 云端分布式渲染平台
- 完整 4D 动态人物世界
- 电影级路径追踪器

先把世界求解闭环做稳。

这才是 888 的核心壁垒。

## 32. AI 驱动下的技术栈优化

AI 主导实现时不改变三语言主架构，但进一步收敛工具链与进程边界，减少 AI 在非核心问题上的自由选择。

### 32.1 固定工具链

- JavaScript / TypeScript：`pnpm`
- Python：`uv`
- Rust：`cargo`
- 跨语言任务入口：`just`

仓库统一提供：

    just setup
    just check
    just test-fast
    just test
    just test-world
    just benchmark

AI 不得自行引入第二套包管理器或重复脚本入口。

### 32.2 Core 与 Worker 通信

早期保持简单、可调试的本地结构化 RPC / stdio 协议。

只传递 Job ID、标准 Schema 数据、Artifact ID / Hash / 本地受控路径引用、Progress、Structured Result、Error。

图片、视频、Mesh、Splat 等大文件不穿 RPC，统一走 Artifact Store。

第一阶段不引入 Kafka、Redis、Kubernetes 或复杂分布式基础设施。

### 32.3 Python 算法边界

第一阶段将 PyCOLMAP / COLMAP、GTSAM、OpenCV、Open3D、PyTorch、gsplat、Nerfstudio 实验路径以及深度、分割、Embedding、Matching 集中在 Python Worker。

Rust Core 只接收标准化输出：CameraCandidate、GeometryCandidate、Evidence、Constraint、ValidationResult。

在算法和 Schema 稳定前，不做不必要的 Rust ↔ C++ FFI 下沉。

### 32.4 单一类型源

所有跨语言协议由 `packages/schema` 生成。

    JSON Schema / IDL
    ↓
    codegen
    ├─ Rust
    ├─ TypeScript
    └─ Python
    ↓
    跨语言 Fixture 一致性测试

新增字段必须先改 Schema，再生成类型，不允许反向手工补类型。

### 32.5 模块插件化、部署不微服务化

继续保留 ReconstructionPlugin、ProviderPlugin、EvaluatorPlugin、CompilerPlugin 等代码模块边界，但默认不拆成独立网络服务。

对于单机本地产品，默认同仓库、少进程、明确协议优先。

### 32.6 AI 友好的可观测性

所有核心任务输出结构化日志，至少包含 trace_id、world_id、job_id、stage、provider、artifact_id、duration、resource_usage、result_state。

禁止仅输出无法机器分析的长文本日志。AI 审计与故障修复优先读取结构化状态，再读取原始日志。
