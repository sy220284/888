# 18 AI 运行时兼容与行为标准

## 1. 目标

888 必须能够接入行为差异很大的 AI，同时保证上层看到的协议、状态、可信度、错误语义和工具行为保持稳定。

系统不追求让所有 AI 用相同方式思考，而是统一它们的**外部行为合同**。

同时必须保留模型之间有价值的差异：有的模型空间推理强，有的视觉强，有的更善于提出新假设，有的结构化输出稳定。888 应利用这些差异，而不是把所有模型压成同质输出。

最终原则：

> **严谨性由协议、证据和验证保证；创意性由受控的候选生成空间保证。**

## 2. 总体架构

    业务层 / World Runtime
              ↓
    Canonical Capability Contract
              ↓
         Provider Router
              ↓
      AI Compatibility Layer
      ├─ Model Registry
      ├─ Behavior Profile
      ├─ Prompt Compiler
      ├─ Tool Adapter
      ├─ Output Normalizer
      ├─ Schema Validator
      ├─ Evidence Validator
      ├─ Confidence Calibrator
      ├─ Creativity Controller
      └─ Conformance Suite
              ↓
    GPT / Claude / Gemini / Qwen / 本地 VLM / 后续模型

上层永远不感知厂商私有 Prompt、Tool Calling 格式和返回结构。

## 3. Canonical Capability Contract

所有 AI 调用先转换为统一 Capability Request。

至少包含：

- request_id
- capability
- input_refs
- world_context_ref
- evidence_policy
- constraints
- output_schema
- quality_profile
- creativity_profile
- cost_budget
- latency_budget
- verification_requirement
- deterministic_seed（模型支持时）
- provider_hints（可选，不允许业务硬绑定厂商）

示例语义：

    capability: ASSOCIATIVE_REASONING
    目标: 寻找可能的空间连接关系
    约束:
      - 不得直接产生 Verified
      - 不得虚构绝对尺度
      - 最多返回 5 个候选
      - 每个候选必须列支持与反对证据
    output: AssociativeProposal[]

业务规则写在 Canonical Contract，不复制到每个 Provider 的业务代码中。

## 4. 两通道输出模型

为了同时保证严谨性和创意性，AI 输出逻辑分成两个通道。

### 4.1 Factual Channel（事实通道）

用于：

- 信息抽取
- 已知对象识别
- 工具调用参数
- Evidence 总结
- Schema 转换
- 可验证的空间 / 几何判断

要求：

- 低自由度。
- 严格 Schema。
- 必须引用输入 Evidence / Observation。
- 不允许无来源事实。
- 高可重复性。

### 4.2 Exploratory Channel（探索通道）

用于：

- 联想
- 多假设生成
- 缺失空间候选
- 创意补全
- 新的验证路径
- 下一最佳观测思路

允许：

- 多样化输出。
- 多方案并行。
- 适当随机性。
- 跨案例联想。
- 模型发挥自身推理风格。

但所有结果必须落成 Candidate / Proposal / Hypothesis，不能直接进入 Observed / Verified。

## 5. Creativity Profile

统一定义创意档位：

### STRICT

- 事实任务默认。
- 最小发散。
- 强证据引用。
- Top-1 / Top-K 很小。

### BALANCED

- 默认联想模式。
- 允许多候选。
- 保持较高可验证性。

### EXPLORATORY

- 用于难解零重叠、缺失区域和创新方案。
- 更高候选多样性。
- 更大 Beam / Top-K。
- 必须增加验证预算。

### DIVERGENT

- 专门用于创意探索或生成多种世界方案。
- 不允许自动进入正式世界。
- 默认需要 Validator 或用户确认。

创意档位影响候选数量和搜索空间，不改变 Evidence 优先级。

## 6. Model Behavior Profile

每个模型必须维护机器可读 Behavior Profile。

至少记录：

- provider_id / model_id / version
- supported_capabilities
- structured_output_reliability
- tool_calling_reliability
- vision_strength
- spatial_reasoning_strength
- associative_reasoning_strength
- creative_diversity
- instruction_following
- uncertainty_calibration
- hallucination_risk
- context_limit
- image_limit
- latency_distribution
- cost_profile
- supported_temperature / seed / reasoning controls
- known_quirks
- benchmark_version

这些值来自固定 Conformance / Benchmark，不允许凭主观印象填写。

## 7. Prompt Compiler

Prompt 分两层：

    Canonical Task Spec
            ↓
       Prompt Compiler
            ↓
    Model-specific Prompt / Tool Spec

Canonical Task Spec 保存业务规则。

Model Compiler 只做：

- 格式适配
- 指令排序适配
- 模型原生 Structured Output 映射
- 工具定义映射
- 图像 / 上下文打包
- 模型特有参数配置

模型更换时不修改业务任务定义。

## 8. Tool Adapter

888 定义统一 AI Tool Protocol。

第一阶段允许的高层工具：

- inspect_world
- query_evidence
- search_observations
- inspect_hypotheses
- propose_relation
- request_validation
- suggest_next_observation

不同厂商的 Function Calling / Tool Use / JSON Command 全部由 Adapter 转换。

无原生工具调用能力的模型可以输出受 Schema 约束的 ToolIntent，再由 Core 验证后执行。

AI 不获得绕过 Command API、直接写 SQLite、直接写 World State 的能力。

## 9. Output Normalizer

任何模型输出离开 Adapter 后都必须转成 888 Schema。

例如联想输出统一为 AssociativeProposal：

- type
- subject
- target
- score_raw
- uncertainty_raw
- supporting_evidence[]
- contradicting_evidence[]
- rationale_summary
- source_model
- source_version
- prompt_compiler_version
- adapter_version

自然语言推理只允许作为可选说明字段，不能成为机器状态真相。

## 10. 多级 Validator

模型输出进入系统前依次通过：

    Syntax / Schema Validator
    ↓
    Semantic Validator
    ↓
    Evidence Validator
    ↓
    Constraint Validator
    ↓
    Policy / Capability Validator
    ↓
    Candidate / Proposal

其中：

- Schema Validator 检查结构。
- Semantic Validator 检查字段语义和互斥关系。
- Evidence Validator 检查引用是否存在、是否支持声明。
- Constraint Validator 检查世界几何 / 拓扑是否冲突。
- Capability Validator 检查模型是否越权输出。

Validator 失败时优先做一次结构化 Repair Prompt；仍失败则标记 Provider Run 失败，不把脏结果送入世界状态。

## 11. Confidence Calibration

模型自己的 0.9 / 90% 不具有跨模型可比性。

888 统一保存：

- raw_confidence
- calibrated_confidence
- calibration_model_version
- calibration_dataset_version

校准来源：

- 固定 Benchmark。
- Capability 分类。
- 模型版本。
- 输入类型。
- 必要时按场景类别分桶。

可采用 reliability curve、isotonic regression、temperature scaling 或其他适合的校准方法。

业务层只使用 calibrated confidence。

## 12. 创意多样性与严谨性解耦

系统不能把“更有创意”简单等同于“降低事实门槛”。

统一采用：

    Creativity ↑
        ↓
    候选数量 / 差异 ↑
        ↓
    Validation Budget ↑
        ↓
    正式世界事实门槛保持不变

即：创意可以扩大搜索空间，但不能降低进入 Canonical World State 的证据门槛。

## 13. Multi-model Ensemble

高难任务允许多模型协同。

模式：

### Parallel Proposal

多个模型独立提出 Proposal，增加候选覆盖率。

### Critic

一个模型提出，另一模型专门找反例、缺失证据和逻辑漏洞。

### Judge-assisted

模型可以提供比较意见，但最终 Accept / Reject 仍由 888 Validator、Evidence、Constraint 和策略决定。

### Specialist Routing

视觉模型负责视觉，相机 / 几何算法负责确定性部分，LLM / VLM 负责联想和验证问题。

禁止使用“两个 AI 都同意”作为 Verified 的充分条件。

## 14. Model Registry 与路由

Router 选择模型时综合：

- Capability 匹配度
- Conformance Score
- 当前任务所需严谨 / 创意比
- 历史成功率
- 置信度校准质量
- 延迟
- 成本
- 本地硬件
- Provider 健康状态

例如：

- 事实抽取优先结构输出稳定模型。
- 零重叠联想优先空间 / 联想 Benchmark 更强模型。
- 创意补全优先多样性更高模型。
- 最终复核优先校准和反幻觉指标更强模型。

## 15. AI Conformance Suite

接入一个新模型必须先通过认证测试。

至少覆盖：

- Schema 输出成功率
- Tool Calling 成功率
- 无证据时是否会强结论
- 是否遵守不得直接 Verified
- 是否遵守绝对尺度 / 6DoF 限制
- Same Entity 正负例
- 零重叠照片
- 室内外关联
- 多假设生成
- 反联想干扰
- Evidence 引用正确率
- 不确定性表达
- Repair Prompt 成功率
- Prompt Injection / 非法 Tool Intent 基础守卫（仅行为协议层）

每个模型生成 Capability Scorecard。

## 16. 严谨性指标

至少包括：

- Schema Compliance
- Evidence Citation Accuracy
- Unsupported Claim Rate
- False High-confidence Association
- Tool Execution Validity
- Calibration Error
- Constraint Violation Rate
- Deterministic Repeatability（适用任务）

## 17. 创意性指标

创意任务单独衡量：

- Proposal Diversity
- Useful Novel Proposal Rate
- Hypothesis Coverage
- Non-duplicate Candidate Ratio
- Evidence-convertible Novelty
- Next Best View Novel Utility
- User / Validator Acceptance Rate

追求有用的新候选，不追求纯文本花样。

## 18. 失败与降级

某模型：

- Schema 不稳定 → 降低结构任务路由权重。
- Tool Calling 不稳定 → 切换 JSON ToolIntent Adapter。
- 幻觉率高 → 只允许 Exploratory Channel。
- 校准差 → 禁止其 raw confidence 参与排序。
- 创意不足 → 不用于 Divergent Profile。
- Provider 不可用 → Router 选择兼容 Provider。

模型能力弱不应该导致 888 上层协议改变。

## 19. 版本与可追溯性

每次 AI Run 必须记录：

- provider
- model
- model_version
- adapter_version
- prompt_compiler_version
- canonical_task_version
- output_schema_version
- behavior_profile_version
- calibration_version
- creativity_profile
- sampling parameters
- input artifact refs
- cost / latency

这样未来模型升级后可以准确回放和比较。

## 20. 第一阶段落地范围

阶段一先实现：

1. Canonical Capability Contract。
2. Provider Adapter 基类。
3. Model Behavior Profile。
4. Prompt Compiler。
5. Output Normalizer。
6. Schema / Evidence Validator。
7. STRICT / BALANCED / EXPLORATORY 三档 Creativity Profile。
8. Conformance Fixture。
9. 基础 Confidence Calibration 数据结构。

Multi-model Ensemble、自动校准模型和 DIVERGENT Profile 可在基础链稳定后增强。

## 21. 最终目标

888 不要求不同 AI 变成同一种 AI。

它要求：

> **模型可以有不同性格、不同推理方式和不同创意上限，但进入 888 后必须遵守同一事实边界、同一工具边界、同一状态语义和同一验收标准。**

这样既保留模型差异带来的创造力，又不会牺牲世界系统的严谨性。
