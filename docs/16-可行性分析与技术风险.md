# 16 可行性分析与技术风险

## 1. 结论

888 在工程上高度可行，核心难点集中在少数需要长期迭代的世界理解与质量闭环能力。

整体判断：

- **工程可行性：约 90%**
- **做到明显超过原 Image Blaster：约 95%**
- **做到高质量连续多图 / 视频场景重建：约 90%**
- **做到跳跃照片、多空间、室内外统一世界：约 75%～85%**
- **做到任意零散照片完全自动、准确恢复真实世界：不能保证**

这些数字是研发规划估计，用于排序风险和资源，不是产品精度承诺。

## 2. 为什么总体可行

888 不依赖先发明新的基础模型。

约 70%～80% 的底层能力可以直接使用成熟技术或成熟生态：

- SfM / Bundle Adjustment：COLMAP / PyCOLMAP
- Factor Graph：GTSAM
- 点云 / Mesh / TSDF：Open3D
- Gaussian Splat：gsplat
- 神经场实验与基线：Nerfstudio
- 分割 / 深度 / Embedding：可替换视觉模型
- 实时 3D：Three.js / React Three Fiber
- 物理：Rapier
- 视频：FFmpeg
- DCC 处理：Blender Headless

888 的研发重点是把这些能力组织成长期稳定、可验证、可重新求解的世界系统。

## 3. 不能承诺的目标

### 单张照片百分百恢复真实世界

不可作为目标。

单张图没有包含：

- 遮挡物背面
- 柜体内部
- 画面外房间
- 不可见连接空间
- 真实绝对尺度（无外部参考时）

系统只能：

1. 恢复观测得到的信息。
2. 推断有约束支持的信息。
3. 保留多种合理假设。
4. 对完全未知区域进行明确标记的生成补全。

因此 888 的目标是“持续收敛到更可信的世界”，不伪装拥有不存在的证据。

## 5. 真正需要 888 自研的壁垒

项目应尽量复用成熟基础设施，把自研投入集中在：

### 5.1 Canonical World State

把所有重建、推断、生成和人工编辑统一到一个可版本化世界状态。

### 5.2 Evidence + Hypothesis

记录系统为什么相信某个关系，以及信息不足时同时保留哪些候选世界解释。

### 5.3 多空间 / 跳跃观测求解

解决照片之间没有连续重叠、甚至室内外分离时的空间拓扑和坐标收敛。

### 5.4 Validation + Repair

从原始相机位重新渲染并判断：

- 相机是否错
- 位置是否错
- 尺度是否错
- 几何是否错
- 材质 / 光照是否错

然后优先局部修正，必要时才重新生成。

### 5.5 Active Capture / Next Best View

计算下一张照片最应该从哪里拍，最大化信息增益。

### 5.6 Associative Prior + 联想求证

在直接证据不足时主动扩大候选空间，再把联想转化为可验证问题。

这是跳跃照片、室内外、零重叠照片能力继续上限提升的关键，但必须严格受 Evidence / Hypothesis / Validation 约束。

## 6. 不应该自研的部分

第一阶段禁止把研发资源耗在：

- 重写 SfM
- 重写通用 Bundle Adjustment
- 从零训练基础视觉模型
- 从零训练通用 Image-to-3D 基础模型
- 自研通用 Gaussian Splat 渲染框架
- 自研完整 DCC 工具
- 大规模云端分布式基础设施

除非后续 Benchmark 证明现有方案成为明确瓶颈。

## 7. 单人 + AI 开发难度

传统纯单人开发：

- **接近 10/10**

普通 AI 辅助：

- **约 8.5～9/10**

在当前 888 已加入：

- AGENTS
- Schema 单一真相源
- ADR
- Fixture / Benchmark
- 架构守卫
- 统一工具链
- 自动测试
- 独立 AI Review

之后：

- **约 7～7.5/10**

仍属于高难度项目，但已经可以通过阶段化方式由一个主开发者 + AI 长期推进。

## 10. 最大技术风险

### 风险 A：弱重叠 / 无重叠照片错误关联

后果：整个世界拓扑被污染。

控制：

- False Merge 高惩罚
- 多假设
- 用户确认
- Evidence 可追溯

### 风险 B：视觉很像但 3D 几何错误

控制：

- RGB + Depth + Silhouette + Camera + Semantic 联合验证
- 不以单一图像相似度作为最终指标

### 风险 C：AI 补全逐渐被当成事实

控制：

- Generated 状态不可自动变成 Observed
- 新真实证据优先替换生成区域

### 风险 D：Provider / 模型升级导致结果漂移

控制：

- 固定模型版本
- Provider Benchmark
- Fixture 回归

### 风险 E：AI 开发导致架构漂移

控制：

- AGENTS
- ADR
- Schema Codegen
- 架构守卫
- 独立 Review

### 风险 F：联想幻觉

后果：

- 错误空间关系被不断强化。
- 相似对象被误合并。
- AI 补全被误认为真实。

控制：

- Proposal 与 Evidence 分层。
- False High-confidence Association 高惩罚。
- 联想不能直接 Verified。
- 新 Evidence 可强制淘汰旧 Proposal。
- Top-K / Beam / Budget 控制联想扩散。

### 风险 G：不同 AI 行为漂移

后果：

- 同一任务换模型后输出语义变化。
- raw confidence 不可比较。
- Tool Calling 行为不一致。
- 新模型更有创意但更容易突破事实边界。

控制：

- Canonical Capability Contract。
- AI Compatibility Layer。
- Model Behavior Profile。
- Prompt Compiler。
- Output Normalizer。
- Confidence Calibration。
- Conformance Certification。
- 严谨 / 创意双通道。

因此更换模型属于 Provider / Profile 升级，不属于业务架构变化。

## 11. 最终技术判断

888 不属于“关键技术尚不存在”的研究项目。

它属于：

> **成熟底层能力 + 少数前沿核心问题 + 高复杂度系统集成**

真正的项目壁垒最终会落在：

```text
证据
+
联想先验
+
多假设
+
空间约束
+
统一世界状态
+
自动验证
+
局部修复
+
主动获取下一份最有价值的观测
```

这些能力稳定后，底层 3D 模型和 Provider 可以持续替换，888 的核心价值仍然成立。
