# 09 任务状态机与故障恢复

## 1. 目标

Job Engine 必须在进程退出、Worker 崩溃、网络错误、Provider 超时后仍能明确知道“任务做到哪里、是否可继续、是否需要回滚”。

## 2. 标准状态机

```text
CREATED
↓
PENDING
↓
READY
↓
RUNNING
├─→ PAUSING → PAUSED → READY
├─→ RECOVERABLE → READY
├─→ FAILED
├─→ CANCELLED
└─→ COMPLETED
```

辅助状态：

- BLOCKED
- WAITING_RESOURCE
- WAITING_PROVIDER
- WAITING_USER

## 3. 状态定义

### CREATED

已建立 Job，但依赖尚未解析。

### PENDING

依赖存在，等待满足。

### READY

依赖全部完成，可调度。

### RUNNING

Worker 正在执行。

### PAUSED

已在安全点保存 Checkpoint。

### RECOVERABLE

执行中断，但存在有效 Checkpoint，可恢复。

### FAILED

不可自动继续或已超过重试上限。

### COMPLETED

Worker 结果写入 Candidate / Artifact Registry，但不意味着世界状态已接受该结果。

## 4. 状态转换规则

所有转换由 Core Job Engine 执行。

Worker 只能上报事件，不能直接修改数据库 Job State。

非法状态转换必须拒绝并记录。

## 5. Checkpoint

适合 Checkpoint 的任务：

- 长时间匹配
- MVS
- Splat 训练
- 批量推理
- 大型导出

Checkpoint 记录：

- job_id
- stage
- progress
- source artifact hashes
- algorithm version
- parameter hash
- checkpoint artifact
- created_at

源输入发生变化时旧 Checkpoint 自动失效。

## 6. Crash Recovery

Core 启动后执行恢复扫描：

1. 查询上次退出时 RUNNING Job。
2. 检查 Worker 是否仍存在。
3. 检查 Checkpoint。
4. 判断输入 Artifact 是否仍有效。
5. 转为 RECOVERABLE / FAILED。
6. 重新建立依赖图。

不得直接把旧 RUNNING 继续标记 RUNNING。

## 7. Worker Lost

Heartbeat 超时时，`WORKER_LOST` 作为故障事件 / 错误码记录，不作为长期持久化 Job State：

```text
RUNNING
↓
检测到 WORKER_LOST 事件
├─ 存在安全 Checkpoint → RECOVERABLE
├─ 无 Checkpoint且任务幂等 → READY / RETRY
└─ 否则 → FAILED
```

## 8. Retry

Job 定义：

- max_attempts
- retry_policy
- backoff
- retryable_error_codes

重试必须区分：

- 算法失败
- Provider 暂时错误
- 输入错误
- 资源不足

INVALID_INPUT 不自动重试。

429 / timeout 可重试。

## 9. 幂等性

可重试 Job 必须满足：

- 临时输出写入临时 Artifact。
- 完成后原子注册。
- 重试不覆盖已接受 Revision。
- 相同参数可命中 Cache。

## 10. Cancel

Cancel 流程：

1. Core 写入取消请求。
2. Worker 在安全点终止。
3. 清理临时资源。
4. 保留诊断日志。
5. Job → CANCELLED。

已注册正式 Artifact 不因取消后续 Job 被自动删除。

## 11. Pause / Resume

Pause 只在支持 Checkpoint 的阶段生效。

恢复前验证：

- Schema Version
- 输入 Hash
- Worker Capability
- 模型版本
- Checkpoint 完整性

任意不一致时重新运行，禁止硬续。

## 12. DAG 依赖

上游失败时：

- 强依赖下游 → BLOCKED。
- 可选依赖 → 允许降级运行。
- fallback 能力 → 创建替代 Job。

依赖语义必须写入 Task Schema。

## 13. 资源调度

资源声明：

- cpu_cores
- ram_mb
- gpu_required
- vram_mb
- disk_temp_mb
- network

Job Engine 不把两个总显存超过 GPU 能力的任务同时调度。

## 14. Provider 任务

远程 Provider Job 额外保存：

- request id
- idempotency key
- remote state
- estimated cost
- actual cost

Core 重启后优先查询远程任务状态，避免重复付费提交。

## 15. 缓存

Cache Key 至少包含：

- 输入 Artifact Hash
- 参数 Hash
- 算法 / 模型版本
- Schema Version
- 代码版本（需要时）

错误结果不得进入正常 Cache。

## 16. 用户可见状态

UI 显示的状态需从 Job State 映射：

- 等待
- 执行中
- 暂停
- 等待资源
- 可恢复
- 已失败
- 已取消
- 已完成

不得只显示泛化“处理中”。

## 17. 验收场景

必须模拟：

- Worker 在 50% 时被强杀。
- Core 被强杀。
- Provider 返回 429。
- GPU OOM。
- 磁盘写失败。
- 用户连续点击两次取消。
- 输入文件在 Checkpoint 后被删除。
- 重启后恢复 Job DAG。

每个场景必须有明确期望状态。
