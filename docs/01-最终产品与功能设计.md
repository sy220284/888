# 01 最终产品与功能设计

## 1. 产品定义

888 是一个“证据驱动的渐进式世界重建与生成系统”。

它不把输入限定为连续拍摄，也不要求用户先理解摄影测量、NeRF、Gaussian Splat 或 3D 建模。用户只需要提供自己已有的照片或视频，系统负责判断这些素材之间的空间关系、恢复能够确认的真实结构、补全缺失部分，并把结果组织成一个持续可修正的完整世界。

最终产品不是“生成一张 3D 图”，而是得到一个可以：

- 进入和自由查看
- 查看每个区域的来源与可信度
- 继续补充照片提高精度
- 编辑空间和物体
- 添加交互与物理
- 导出到游戏、影视、VR、AR 或 DCC 工具

的世界工程。

---

## 2. 最终效果目标

### 2.1 最低输入：单张照片

单张照片模式用于快速启动。

系统应：

1. 分析场景类型、主要空间结构、相机视角和可见对象。
2. 建立初始深度、平面、对象和空间关系。
3. 对可见部分尽量重建。
4. 对不可见区域建立明确的“未知”或低置信假设。
5. 必要时使用生成模型补齐可进入空间。
6. 输出一个可浏览的初始 3D 世界。
7. 明确告诉用户哪些部分是观测恢复，哪些部分是 AI 推断。

单图目标是“快速形成合理世界”，而不是承诺不存在的信息可以被真实恢复。

### 2.2 多张连续照片

当照片存在较强视觉重叠时：

- 恢复相机位姿。
- 进行多视图几何重建。
- 融合深度。
- 建立更加可靠的尺度和空间结构。
- 用多张照片共同约束纹理、材质与对象形状。
- 优先替换单图阶段的 AI 补全。

### 2.3 多张跳跃式照片

这是 888 的核心能力之一。

例如：

- 照片 A：客厅左侧
- 照片 B：厨房
- 照片 C：客厅右侧
- 照片 D：二楼
- 照片 E：后院

系统不能把这些照片分别生成后“硬拼”。

正确流程：

1. 为每张照片建立独立 Observation。
2. 判断是否存在视觉重叠。
3. 有重叠：进行几何匹配。
4. 无直接重叠但存在共享对象 / 门窗 / 墙体 / 材质 / 拓扑关系：建立语义锚点。
5. 完全无共同证据：只建立空间假设，不伪造精确位置。
6. 保留多个候选关系，等待后续证据消歧。
7. 形成统一世界拓扑。

### 2.4 室内 + 室外

室内和室外不作为两个独立项目，而作为同一个世界里的不同 Zone。

系统使用以下信息连接它们：

- 门、窗、阳台、楼梯等 Portal
- 同一建筑立面
- 相同结构边缘
- 相同固定物体
- 相机方向
- 深度与尺度
- EXIF
- GPS
- 用户说明

若没有足够证据，系统保留多个假设，例如：

- 客厅位于一楼东侧：42%
- 客厅位于一楼西侧：35%
- 客厅位于二楼东侧：18%

而不是强行选一个答案。

### 2.5 多楼层 / 多建筑 / 大场景

世界可进一步拆分为：

- Building
- Floor
- Zone
- Room
- Outdoor Area
- Transition Space

跨楼层使用楼梯、电梯、楼板结构、窗外高度差等约束。

大型环境可按空间块流式加载，不要求一次全部载入。

## 3. 渐进式世界重建

系统不是一次性任务。

任何时刻都允许用户新增素材：

```text
当前世界
  ↓
加入新照片 / 视频
  ↓
新观测进入证据图
  ↓
重新计算空间关系
  ↓
淘汰错误假设
  ↓
更新世界状态
  ↓
替换低可信生成内容
```

例如系统之前 AI 补了一个玄关。

后来用户补了一张门口照片：

- 新照片与客厅门框匹配。
- 重新确定室内外相对位置。
- 删除旧的生成玄关。
- 用新证据重新建模。
- 保留版本历史，允许回滚。

---

## 4. 世界可信度可视化

所有世界内容必须区分来源状态。

建议基础状态：

- **Observed**：直接来自真实观测。
- **Verified**：被多个独立观测或强约束验证。
- **Inferred**：由几何 / 语义 / 规则推断。
- **Hypothesis**：尚未确认的候选关系。
- **Generated**：由生成模型补全。
- **UserConfirmed**：用户人工确认。
- **Rejected**：已被证据否决。

用户可在编辑器中切换“可信度视图”。

例如：

- 绿色：多证据验证
- 普通显示：已确认
- 半透明：推断
- 虚线轮廓：假设
- 特殊遮罩：AI 生成补全

颜色只是 UI 表达，数据层不得把视觉颜色和状态绑定死。

---

## 5. 主动补拍：下一最佳观测

系统不能只说“多拍一些”。

应主动判断当前最大的不确定性来自哪里，并推荐最有价值的一张照片。

示例：

> 当前客厅与庭院之间的空间关系不确定。建议站在客厅门口向室外拍摄，让门框、外墙和庭院同时进入画面。

这一张图可以同时解决：

- 门尺寸
- 墙厚
- 室内外朝向
- 建筑尺度
- 两个 Zone 的相对位置

推荐应给出：

- 建议站位
- 朝向
- 必须拍入的锚点
- 预计可以解决的问题
- 信息增益

后续可以增加 AR 引导框。

---

## 6. 自动空间补全

补全必须遵循优先级：

1. 真实观测重建
2. 多视图几何推断
3. 单目深度 / 平面 / 结构估计
4. 规则化建筑结构补全
5. 资产库匹配
6. 生成式补全

生成内容永远不是“事实”。

它应附带：

- 来源模型
- 输入证据
- 生成时间
- 关联假设
- 可信度
- 可替换状态

---

## 7. 混合 3D 世界

不同区域采用不同表示，不强制统一成一种格式。

### 适合 Mesh

- 建筑结构
- 家具
- 可碰撞物体
- 可编辑物体
- 需要动画的对象

### 适合 Gaussian Splat

- 复杂静态环境
- 植被
- 难以高质量网格化的视觉区域
- 远景

### 适合 NeRF / Neural Representation

- 高视觉还原但无需直接编辑的区域
- 需要视角相关外观的场景

### 适合 Billboard / Impostor

- 很远的背景元素
- 移动端低成本呈现

系统对用户呈现为统一场景，对编译器保留真实表示类型。

---

## 8. 对象与角色

系统从场景中识别：

- 固定结构
- 可移动物体
- 重复资产
- 人物
- 动物
- 植物
- 车辆
- 设备

每个 Entity 具有独立身份，而不是只保存一个模型文件。

它包含：

- 语义
- 几何
- 材质
- 物理
- 动画
- 观测证据
- 不同版本
- 生成资产
- 世界位置
- 时间状态

角色后续可增加骨骼、动作和行为，但角色逻辑不是第一阶段核心。

---

## 9. 世界编辑器

用户必须可以直接修改世界。

基础编辑能力：

- 选择
- 移动
- 旋转
- 缩放
- 删除
- 替换资产
- 修改材质
- 修改光照
- 切换版本
- 查看证据
- 查看来源照片
- 锁定真实约束
- 接受 / 拒绝假设
- 手工建立两个空间的关系
- 标记某区域“不要 AI 猜”

系统修改后重新运行局部验证，而不是全世界重新生成。

---

## 10. 自动质量闭环

每次关键生成或重建后：

1. 从已知真实相机位渲染当前世界。
2. 与真实照片比较。
3. 计算视觉、深度、几何和语义误差。
4. 判断误差属于：
   - 相机
   - 尺度
   - 位置
   - 几何
   - 材质
   - 光照
   - 遮挡
   - 错误对象
5. 优先调整现有参数。
6. 无法修复时才重新生成局部资产。
7. 验证通过后提升状态。

这是系统和普通“一次生成式 Demo”的关键区别。

## 11. 世界编译与导出

统一世界状态可编译为不同目标。

### Web

- glTF / GLB
- Splat
- WebGPU / WebGL
- LOD
- 流式加载

### Blender

- Mesh
- PBR
- Camera
- Light
- Collection / Hierarchy
- USD / glTF

### Unity / Unreal / Godot

- 场景层级
- Mesh
- Collider
- 材质
- 贴图
- LOD
- 可选动画与音频

### AR / VR

- 尺度校正
- USDZ / glTF
- 空间锚点
- 轻量碰撞

编译过程根据目标平台生成不同资产，不修改 Canonical World State。

## 12. 时间维度

第一版不需要完整实现，但核心数据模型必须预留。

同一 Entity / Zone 可以具有多个时间状态。

例如：

- 2026-01：旧沙发
- 2026-05：新沙发
- 2027-01：墙面重新粉刷

系统应区分：

- 物体发生变化
- 物体移动
- 物体消失
- 新物体出现
- 固定结构不变

最终可形成 4D World，但不得让时间功能干扰第一阶段 3D 核心落地。

---

## 13. 产品设计原则

1. 用户输入可以混乱，系统内部必须有秩序。
2. 不确定必须显式，不允许假装确定。
3. 能局部修复就不全量重做。
4. 真实证据优先于生成结果。
5. 新证据可以推翻旧推断。
6. 底层算法变化不能破坏世界数据。
7. 世界数据与渲染表现分离。
8. 世界数据与 Provider 分离。
9. 任务执行与 Agent 分离。
10. 用户看到的是简单流程，复杂性留在系统内部。

---

## 14. 联想式世界理解

888 在证据驱动之上增加第二条推理链：**联想式世界理解**。

它负责在信息不完整时主动提出：

- 哪些照片可能描述同一对象 / 同一空间。
- 两个 Zone 之间可能怎样连接。
- 完全缺失区域可能存在什么结构。
- 哪些已有素材值得继续搜索。
- 下一张照片最值得从哪里拍。

联想结果统一进入 Associative Proposal / Prior，不直接进入正式世界。

用户体验上，系统可以表达：

> “我怀疑客厅右侧门可能连接庭院，但现在证据不足。如果补一张同时包含门框和外墙的照片，可以快速验证。”

因此最终交互闭环升级为：

    观察
    → 证据
    → 联想
    → 多假设
    → 求证
    → 收敛
    → 重建 / 生成
    → 验证 / 修复

普通用户只看到“可能关系 + 为什么不确定 + 怎么验证”，不需要理解内部推理链。
