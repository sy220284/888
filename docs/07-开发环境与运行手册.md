# 07 开发环境与运行手册

## 1. 目标

本手册用于统一 888 的本地开发环境、依赖安装、启动方式、诊断方法和常用命令，避免不同 AI 或开发者重复研究运行路径。

所有开发环境优先通过根目录 `justfile` 进入。

## 2. 支持平台

第一阶段支持：

- Windows 11
- macOS
- Ubuntu 22.04 / 24.04

算法开发首选：

- Linux + NVIDIA CUDA

产品运行目标：

- Windows
- macOS
- Linux

## 3. 固定工具链

### 通用

- Git
- just
- FFmpeg
- Blender（需要导出 / 网格处理时）

### 前端

- Node.js LTS
- pnpm

### Core

- Rust Stable
- cargo

### Vision / AI

- Python 3.11 或项目锁定版本
- uv

不得自行混用 npm / yarn / bun、pip / poetry / conda 等第二套项目级包管理路径。

## 5. 标准安装入口

最终统一：

```bash
just setup
```

该命令负责：

1. 检查 Rust。
2. 检查 Node / pnpm。
3. 检查 Python / uv。
4. 安装前端依赖。
5. 安装 Rust 依赖。
6. 建立 Python 虚拟环境。
7. 安装 Worker 基础依赖。
8. 检查 FFmpeg。
9. 输出 COLMAP / CUDA / Blender 可用性。
10. 生成本地开发配置模板。

安装失败必须明确指出缺失组件，不能静默跳过。

## 6. 标准开发命令

```bash
just check
just test-fast
just test
just test-world
just benchmark
just dev
```

建议语义：

- `just check`：格式、Lint、类型、Schema、架构边界。
- `just test-fast`：不需要重型 GPU 的快速测试。
- `just test`：常规完整测试。
- `just test-world`：真实世界 Fixture / 3D 链路。
- `just benchmark`：性能基准。
- `just dev`：启动 Desktop + Core + Worker。

## 7. GPU 检测

Worker 启动时必须输出标准能力声明：

```json
{
  "device": "cuda",
  "device_name": "NVIDIA ...",
  "vram_gb": 16,
  "capabilities": ["MATCHING", "DEPTH", "SPLAT_TRAIN"]
}
```

支持状态：

- CUDA：首选。
- Apple MPS：支持可运行的模型。
- CPU：提供降级路径。
- 其他 GPU：按模型能力注册，不伪报。

Job Engine 根据 Worker Capability 分配任务。

## 8. CUDA 与模型依赖

CUDA 版本由项目锁定文件和 CI 确定。

不得让每个 Worker 自行选择任意 PyTorch / CUDA 组合。

新增 CUDA-only 模型时必须补：

- 支持 CUDA 版本
- 最低显存
- CPU / MPS 是否可用
- 无法运行时的 fallback

## 9. 本地配置

本地配置只保存运行参数，不保存项目世界真相。

配置类型：

- Worker 路径
- 模型缓存目录
- Provider Endpoint
- API Key 引用
- GPU 偏好
- Blender / FFmpeg 路径
- 临时目录

配置文件格式必须有版本。

## 10. 模型缓存

模型权重统一进入可配置缓存目录。

禁止：

- 把大模型权重提交进 Git。
- 每个 Worker 重复下载同一模型。
- 用临时目录作为永久模型位置。

模型缓存记录：

- 模型 ID
- 版本 / Revision
- Hash
- 来源
- 占用空间

## 11. 启动顺序

标准启动：

```text
Desktop
↓
Core
↓
加载项目 / 数据库
↓
启动或发现 Worker
↓
Worker 注册 Capability
↓
UI 显示 Ready
```

Worker 启动失败时，Desktop 仍应能进入项目并显示具体能力不可用。

## 12. 常见故障诊断

### Python Worker 无法启动

依次检查：

1. uv 环境存在。
2. Python 版本匹配。
3. Native dependency 可加载。
4. CUDA / MPS 可见。
5. Worker 注册日志。

### COLMAP 不可用

检查：

- PyCOLMAP 是否安装。
- 系统 COLMAP 是否被当前路径引用。
- CUDA build 是否与系统匹配。

### GPU OOM

处理顺序：

1. 降低任务 batch。
2. 释放旧任务资源。
3. 使用低显存 Profile。
4. 切换 CPU / 远程 Provider（若能力允许）。
5. 明确返回 RESOURCE_EXHAUSTED。

### Blender 不可用

只影响依赖 Blender 的 Tool Job，不得导致整个 888 启动失败。

## 13. 环境检查输出

`just doctor` 应输出：

- 操作系统
- CPU / RAM
- GPU / VRAM
- Rust
- Node / pnpm
- Python / uv
- CUDA
- COLMAP
- FFmpeg
- Blender
- 关键目录写权限
- Worker Capability

## 14. AI 执行规则

AI 遇到环境问题时：

1. 先运行标准诊断入口。
2. 依据结构化结果定位。
3. 不自行发明第二套安装路径。
4. 若必须改变固定版本，先更新本手册及锁定文件。
