# 17 联想推理与先验系统设计

## 1. 定位

888 的世界理解采用“双引擎”：

- **证据引擎**：回答“我们真正观察到、测量到、验证到什么”。
- **联想引擎**：回答“基于现有证据与世界常识，接下来有哪些值得验证的可能性”。

最终范式定义为：

> **Evidence-grounded Associative World Compiler（证据锚定的联想式世界编译器）**

联想扩大候选空间，证据与约束决定候选能否进入正式世界。

## 2. 核心边界

联想结果永远不能直接成为 Verified Fact。

正确链路：

    Observation / Evidence
            ↓
    Associative Engine
            ↓
    Associative Proposal / Prior
            ↓
    Hypothesis Graph
            ↓
    Constraint / Evidence Verification
            ↓
    Verified / Rejected / Keep Pending

联想层负责提出可能性，不得负责宣布事实。

## 3. 联想来源

### 3.1 空间结构先验

- 门连接两个空间。
- 窗通常位于外墙。
- 楼梯意味着高度变化。
- 厨房、餐厅、客厅可能形成高频拓扑组合。
- 卫生间更可能邻近管线集中区域。

这些只作为 Prior，不作为事实。

### 3.2 对象共现先验

- 沙发 + 电视 + 茶几 → 客厅候选。
- 床 + 床头柜 → 卧室候选。
- 灶台 + 水槽 → 厨房候选。

### 3.3 视觉联想

通过视觉 Embedding / Retrieval 找到相似空间、家具、建筑立面、材质与房型。候选技术包括 DINO、SigLIP、CLIP 类表征和可替换视觉 Embedding Provider。

### 3.4 案例检索

从已有已验证世界中检索类似结构，形成 Case-based Prior。检索结果必须保留 case_id、similarity、matched_features、applicability。

### 3.5 VLM / LLM 世界常识推理

VLM / LLM 可用于提出可能存在的空间、值得匹配的对象、可能的连接关系、缺失区域候选和验证问题。大模型输出只能进入 Proposal，不能直接写入 World State。

### 3.6 生成式空间假设

完全未知区域允许一次产生多个候选，例如：

    候选 A：客厅 → 玄关 → 正门
    候选 B：客厅 → 走廊 → 玄关 → 正门
    候选 C：客厅 → 侧门 → 庭院

随后由证据、空间约束、Validator 与新观测继续筛选。

## 4. Associative Prior Graph

新增逻辑图层：

    Evidence Graph
          ↓
    Associative Prior Graph
          ↓
    Hypothesis Graph
          ↓
    Constraint Solver

Prior 节点至少记录：prior_id、prior_type、subject、object / target、source、source_version、score、uncertainty、supporting_evidence、contradicting_evidence、created_by_job、invalidates_on。

## 5. Prior 类型

第一阶段建议：

- SPATIAL_TOPOLOGY_PRIOR
- ROOM_TYPE_PRIOR
- OBJECT_COOCCURRENCE_PRIOR
- SAME_ENTITY_PRIOR
- SAME_ZONE_PRIOR
- PORTAL_PRIOR
- MISSING_REGION_PRIOR
- MATERIAL_STYLE_PRIOR
- NEXT_OBSERVATION_PRIOR

Prior Registry 统一管理，不允许业务代码随意发明字符串。

## 6. 评分

联想分数不是事实概率。总分应保留视觉相似、语义兼容、几何兼容、拓扑先验、案例相似、时间兼容、冲突惩罚等分量，禁止只保存一个黑盒总分。

## 7. 联想与 Hypothesis

一个 Proposal 可以创建新 Hypothesis、提升已有候选分、提供验证目标、被证据否决或因新世界状态失效。Proposal 本身不等于 Hypothesis 的最终评分。

Hypothesis 最终还要结合真实 Evidence 与 Solver Residual。

## 8. 联想 → 求证

这是联想能力最重要的闭环：

    联想提出可能关系
    ↓
    计算当前最缺的证据
    ↓
    生成验证任务
    ↓
    已有素材继续搜索 / Next Best View 推荐补拍
    ↓
    得到新证据
    ↓
    验证 / 否决联想

例如系统联想到“客厅右侧门可能通向庭院”，下一步就优先寻找或建议拍摄同时包含右侧门框与外墙 / 庭院的照片。

## 9. 零重叠照片

两张完全无共同像素的照片仍可建立 Weak Associative Proposal，但只能进入低权重 Hypothesis。禁止因为看起来很像就直接产生精确 6DoF Transform。

## 10. 联想记忆 / 案例库

后期允许积累已验证世界经验库，只保存已验证拓扑模式、对象关系、空间结构和可授权案例特征。案例库只提供 Prior，不污染当前项目 Evidence。

## 11. 与 Canonical World State 的关系

Canonical World State 仍是唯一正式世界状态。Provenance 增加来源类型：OBSERVED、VERIFIED、INFERRED、ASSOCIATIVE、GENERATED、USER_CONFIRMED。

ASSOCIATIVE 表示该 Candidate / Hypothesis 曾由联想先验提出。**ASSOCIATIVE 不能单独成为正式 Verified 依据。**

## 12. 与生成补全的关系

生成模型不能把单个联想直接实体化后自动写入世界。正确路径是：多个 Associative Proposal → Hypothesis Branches → 多个 Completion Candidates → 约束验证 / 原视角重渲染 → 保留最佳候选或继续等待证据。

## 13. 技术实现

第一阶段建议：

- 视觉先验：DINO / SigLIP / CLIP 类 Embedding、Object / Scene Retrieval、本地 ANN Vector Index。
- 结构先验：可审计规则、房间 / Portal / 建筑拓扑规则、Entity Co-occurrence Table。
- Case Retrieval：已验证 World Pattern Index。
- VLM / LLM：通过 Provider Router 暴露 ASSOCIATIVE_REASONING、SCENE_HYPOTHESIS、VERIFICATION_QUESTION，并返回结构化 Proposal Schema。

## 14. 运行位置

- Prior / Proposal Schema：packages/schema
- Prior 状态管理：Rust Core
- Embedding / Retrieval / VLM 推理：Python Worker 或远程 Provider
- Hypothesis 合并与生命周期：Rust Core
- Factor / Constraint 求解：Python Worker + GTSAM
- 正式 Revision：Rust Core

## 15. 成本控制

联想不能对所有世界节点无限展开。必须使用 Top-K、Beam Width、Minimum Score、Uncertainty Threshold、Region Importance、Token / Provider Budget、Duplicate Proposal Merge。低价值 Proposal 自动淘汰。

## 16. 反幻觉规则

1. 联想不生成 Observed。
2. 联想不生成 Verified。
3. 联想不能单独创建绝对尺度。
4. 联想不能单独创建精确相机位姿。
5. 联想无法覆盖强真实 Evidence。
6. 新真实证据与联想冲突时，真实证据优先。
7. 联想来源与模型版本必须可追溯。

## 17. 质量指标

- Proposal Recall
- Proposal Precision
- Useful Hypothesis Rate
- False High-confidence Association
- Evidence Conversion Rate
- Next Best View Information Gain
- Hypothesis Resolution Rate

其中 False High-confidence Association 属于高风险指标。

## 18. 用户体验

默认不向普通用户展示模型联想链，只显示系统发现的可能关系、当前可信度、为什么还不确定、可以补什么证据。高级模式才显示 Prior 来源、支持 / 反对证据、Case Retrieval、VLM Proposal、Hypothesis Branch。

## 19. 第一阶段实现范围

先实现三类最有价值联想：

1. Same Entity / Same Anchor 联想。
2. Zone / Portal 拓扑联想。
3. 联想驱动 Next Best View。

暂不优先实现大型长期案例库或复杂世界常识知识图谱。

## 20. 最终目标

888 的推理闭环最终变为：

    观察
    ↓
    证据
    ↓
    联想
    ↓
    假设
    ↓
    求证
    ↓
    收敛
    ↓
    重建 / 生成
    ↓
    验证 / 修复
    ↺

证据负责约束真实边界，联想负责发现下一步值得探索的可能性。

## 21. 联想的严谨 / 创意双通道

联想系统通过 AI Compatibility Layer 获得模型无关行为。

### Factual Channel

负责：

- 提取已有 Evidence。
- 判断明确约束。
- 生成验证问题中的已知部分。

使用 STRICT Profile。

### Exploratory Channel

负责：

- 提出新的空间连接可能。
- 补充低概率但有价值的 Hypothesis。
- 产生多种缺失区域候选。
- 寻找非显而易见的 Next Best View。

使用 BALANCED / EXPLORATORY Profile。

关键原则：

- Exploratory 可以提高 Proposal Diversity。
- Exploratory 不提高 Proposal 的事实权重。
- 创意模型输出仍经过 Evidence Validator / Constraint Validator。
- 不同 AI 的 raw confidence 先校准后再参与 Hypothesis 排序。

这样联想系统既可以利用模型的创造力，又不会因为模型风格差异破坏证据锚定原则。
