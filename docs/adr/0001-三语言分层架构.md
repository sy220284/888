# ADR 0001：采用 Rust + TypeScript + Python 三语言分层架构

- 状态：已接受
- 日期：2026-10-05

## 背景

888 同时包含桌面 UI、实时 3D、稳定状态管理、任务调度以及快速变化的计算机视觉 / AI 算法。

单一语言可以降低表面复杂度，但会牺牲某些层的生态或可靠性。

## 决策

- TypeScript / React：界面、交互、Three.js 编辑器。
- Rust：Core、世界正式状态、数据库、任务系统、Worker 管理。
- Python：CV、AI、重建、GTSAM、PyCOLMAP、Open3D、gsplat。

通过权威 Schema 与明确进程协议连接。

## 原因

- Python 拥有最完整的 AI/CV 生态。
- Rust 适合长期稳定的本地核心与并发任务系统。
- TypeScript 与 Three.js / React 的交互生态成熟。
- 每一层职责清楚，AI 更容易在局部上下文内修改。

## 放弃方案

### 全 Python

开发快，但长期桌面 UI、任务调度、状态可靠性与大型工程维护成本更高。

### 全 TypeScript

AI/CV/3D 重建生态不足。

### Rust 承担全部算法

会增加 C++ / CUDA / Python 模型接入难度，降低算法迭代速度。

## 后果

需要承担跨语言 Schema、Worker 通信和多工具链成本。

因此必须：单一 Schema 真相源、统一 just 命令、Worker 不直接写正式世界。
