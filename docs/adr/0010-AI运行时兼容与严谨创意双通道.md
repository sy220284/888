# ADR 0010：采用 AI 运行时兼容层与严谨 / 创意双通道

- 状态：已接受
- 日期：2026-10-05

## 背景

888 需要接入 GPT、Claude、Gemini、Qwen、本地 VLM / LLM 以及未来模型。

不同模型在以下方面差异明显：

- Structured Output
- Tool Calling
- 指令遵循
- 视觉与空间推理
- 联想能力
- 置信度表达
- 幻觉倾向
- 创意多样性

如果业务层直接适配每个模型，将导致 Prompt、工具、错误语义和状态规则分叉。

## 决策

在 Provider Router 与具体 AI 之间增加 **AI Runtime Compatibility Layer**。

核心组成：

- Canonical Capability Contract
- Model Registry
- Behavior Profile
- Prompt Compiler
- Tool Adapter
- Output Normalizer
- Validator Chain
- Confidence Calibrator
- Creativity Controller
- Conformance Suite

## 双通道

### Factual Channel

用于事实抽取、工具参数、Evidence 总结和关键验证。

特点：

- 低自由度
- 强 Schema
- 强 Evidence 引用
- 高稳定性

### Exploratory Channel

用于联想、多假设、缺失空间和创意补全。

特点：

- 允许多样性
- 允许多候选
- 允许模型发挥差异化优势

但只能产生 Proposal / Hypothesis / Candidate。

## 核心原则

1. 不要求不同 AI 内部推理一致。
2. 要求所有 AI 的外部行为合同一致。
3. 厂商差异止步于 Adapter。
4. raw confidence 不跨模型直接比较。
5. 业务使用 calibrated confidence。
6. 创意只扩大候选空间，不降低事实准入门槛。
7. 多模型共识不能替代 Evidence / Constraint Verification。
8. 新模型通过 Conformance Suite 后才能进入默认自动路由。

## 原因

该方案可以同时获得：

- 模型可替换性
- 行为稳定性
- 更可靠的世界状态
- 不同模型的特长利用
- 可控的创意多样性
- 可量化的模型选择依据

## 后果

需要新增：

- AI 兼容层 Schema
- Model Behavior Profile
- Prompt Compiler
- Tool Adapter
- Output Normalizer
- Calibration Profile
- AI Conformance Fixture
- 严谨性与创意性双指标

详细规范见 `docs/18-AI运行时兼容与行为标准.md`。
