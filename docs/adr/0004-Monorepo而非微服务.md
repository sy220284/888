# ADR 0004：保持 Monorepo，不采用微服务优先架构

- 状态：已接受
- 日期：2026-10-05

## 背景

888 有多个逻辑模块与多个运行进程，但主要目标是单机桌面应用，并计划高比例使用 AI 推进开发。

## 决策

所有核心模块放在同一个 GitHub 仓库中。模块之间保持清晰边界，但不因为模块化自动拆成独立网络服务。

## 原因

- AI 可以一次检查完整影响范围。
- Schema 与测试可以原子更新。
- 重构成本低。
- CI 与 Fixture 更统一。
- 本地应用没有使用复杂分布式系统的必要。

## 默认禁止

在没有明确数据证明必要前，不引入 Kafka、Redis 作为架构必需、Kubernetes、大量独立 HTTP 服务、多仓库拆分。

## 后果

需要通过代码边界、模块依赖检查和进程协议保持解耦，而不能依赖网络隔离制造假解耦。
