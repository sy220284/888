# 12 性能预算与硬件兼容

## 1. 目标

性能目标必须在开发早期冻结，否则后续无法判断“优化是否有效”以及“某项功能是否超出产品可接受范围”。

888 的性能预算分为：

- UI 实时性能
- 项目加载性能
- Core / 数据库性能
- Worker / 算法性能
- GPU / VRAM
- 内存
- 磁盘
- 导出性能

## 2. 设备等级

### L0：基础设备

目标：

- 无独立 GPU 或显存极低
- 可进行项目管理、查看结果、轻量编辑
- 重型任务通过远程 Provider 或禁用

建议：

- 16GB RAM
- SSD
- CPU 4～8 核

### L1：标准本地设备

目标：

- 支持常规 CV
- 小型 Mesh
- 小型 Splat
- 默认用户路径

建议：

- 32GB RAM
- 8 核以上 CPU
- 8～12GB VRAM

### L2：推荐开发设备

目标：

- 多视图重建
- 常规 Splat 训练
- 深度 / 分割并行
- 中型世界

建议：

- 64GB RAM
- 12 核以上 CPU
- 16～24GB VRAM
- NVMe 1TB+

### L3：高性能设备

目标：

- 大型世界
- 高质量训练
- Benchmark
- 多任务并发

建议：

- 128GB RAM+
- 24GB+ VRAM
- 高性能 NVMe

## 3. GPU 平台

### NVIDIA

首选算法开发平台。

支持：

- CUDA
- PyTorch CUDA
- gsplat
- COLMAP CUDA 路线
- 大多数视觉模型

### Apple Silicon

支持：

- MPS 可运行模型
- CPU / MPS 混合
- 编辑与 Viewer

如果某算法只支持 CUDA，必须标记 Capability 不可用或选择 fallback。

### AMD

根据 PyTorch / ROCm / 算法兼容情况逐项注册 Capability，不做虚假“全支持”。

### 无 GPU

至少支持：

- 项目打开
- UI
- 世界浏览
- 数据管理
- 轻量 CPU 分析
- 远程 Provider 路径

## 4. Viewer 性能目标

### 桌面标准设备

目标：

- 普通编辑场景：60 FPS 优先
- 大型场景：不低于 30 FPS
- UI 操作不能因后台 Worker 阻塞

Viewer 采用：

- LOD
- Frustum Culling
- Chunk Streaming
- Texture Streaming
- Splat 分级加载

## 5. 项目打开预算

### Small

- ≤ 50 Observations
- 1～3 Zones

目标：

- 项目元数据加载 < 1 秒
- 可交互 < 2 秒

### Medium

- ≤ 500 Observations
- ≤ 20 Zones

目标：

- 元数据加载 < 3 秒
- 初步可交互 < 5 秒

### Large

- ≤ 5000 Observations

目标：

- 不全量加载大资产
- 元数据分页 / 延迟加载
- 初步可交互 < 10 秒

## 6. 内存预算

原则：

- SQLite 查询不一次加载完整世界大对象。
- 大图片按需读取。
- Viewer 使用可释放 Resource Pool。
- Worker 任务结束后显式释放 GPU Tensor。
- Splat / Mesh 使用分块。

每个 Job 必须声明预估内存与显存。

## 7. VRAM 调度

Job Engine 根据：

- 当前空闲 VRAM
- 任务预估 VRAM
- Safety Margin

决定是否并行。

建议至少保留 10%～15% 安全空间。

GPU OOM 后：

1. 标记资源错误。
2. 释放 Worker 缓存。
3. 使用低显存 Profile 重试。
4. 仍失败则明确返回。

## 8. 磁盘预算

大项目主要占用：

- 原图 / 视频
- Depth
- Point Cloud
- Mesh
- Splat
- 模型 Cache
- Export

Artifact Store 必须统计：

- 项目占用
- Cache 占用
- 临时文件
- 可回收 Artifact

提供 GC 预览后再删除。

## 9. 网络与 Provider

远程任务记录：

- 上传数据量
- 下载数据量
- API 延迟
- 服务排队时间
- 总完成时间

网络超时不与模型计算时间混为一个指标。

## 10. 算法性能指标

每种 Worker Capability 至少记录：

- 输入规模
- 设备
- 耗时
- Peak RAM
- Peak VRAM
- 成功率

用于 Router 和 Benchmark。

## 11. Benchmark Profile

固定 Profile：

- SMALL_CPU
- SMALL_GPU
- STANDARD_12GB
- STANDARD_24GB
- LARGE_24GB_PLUS

Benchmark 结果与代码版本绑定。

## 12. 性能回归门槛

默认规则：

- 非明确优化 PR 不允许关键路径性能恶化 > 10%。
- 若质量显著提升导致性能下降，PR 必须明确给出收益与代价。
- 内存泄漏属于阻断问题。

## 13. AI 开发要求

AI 修改核心算法时必须检查：

- 时间复杂度是否改变。
- 是否引入全量加载。
- 是否增加重复模型实例。
- 是否把大文件塞入 IPC。
- 是否造成 GPU 生命周期泄漏。

没有 Benchmark 数据时不得宣称“性能已优化”。
