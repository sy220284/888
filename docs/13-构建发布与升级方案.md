# 13 构建发布与升级方案

## 1. 目标

888 最终是本地桌面应用，发布必须同时解决：

- Desktop 打包
- Rust Core
- Python Worker
- Native 工具
- 模型与缓存
- 数据库升级
- Schema 升级
- 应用自动更新
- 失败回滚

## 2. 发布产物

按平台输出：

### Windows

- Installer
- Desktop App
- Core
- Worker Runtime
- 必需 Native DLL / 工具

### macOS

- .app / dmg
- 签名
- 公证
- Apple Silicon 优先

### Linux

- AppImage / deb（后续可选）
- Worker Runtime

## 3. 版本模型

应用版本采用语义化版本：

```text
MAJOR.MINOR.PATCH
```

同时维护：

- app_version
- schema_version
- protocol_version
- worker_version
- provider_adapter_version

它们不能混成一个字段。

## 4. 构建流水线

```text
源码
↓
Schema Codegen
↓
前端构建
↓
Rust Core 构建
↓
Python Worker 锁定与打包
↓
Native Tool 校验
↓
集成测试
↓
打包
↓
签名
↓
安装测试
↓
发布
```

## 5. Python Worker 分发

优先方案：

- 独立受控 Runtime
- uv lock 固定依赖
- 应用首次安装 / 更新时校验环境

不得依赖用户系统 Python。

Worker 包应记录：

- Python 版本
- Lock Hash
- Worker Version
- Native dependency 信息

## 6. Native 工具

分类：

### 必须随应用或明确安装

- FFmpeg（若许可与分发方式允许）
- 必需 runtime

### 可外部发现

- Blender
- 系统级 COLMAP（若选择）

如果工具不存在：

- 明确 Capability 不可用
- 不影响整个应用启动

## 7. 模型分发

大模型默认不全部塞入安装包。

采用：

```text
首次使用对应 Capability
↓
检查模型缓存
↓
下载指定版本
↓
Hash 验证
↓
注册可用
```

支持离线预装目录。

## 8. 数据库 Migration

应用启动：

1. 读取 DB Schema Version。
2. 检查目标版本。
3. 创建备份点。
4. 执行 Migration。
5. 验证。
6. 成功后提交。

Migration 失败：

- 不打开写模式。
- 保留原数据库。
- 显示可诊断错误。

## 9. World Schema Migration

Canonical World State 的 Breaking Change 必须有：

- from_version
- to_version
- migration code
- fixture
- rollback / backup strategy

不得要求用户删除旧项目重新创建。

## 10. 自动更新

更新流程：

```text
检查版本
↓
下载
↓
签名验证
↓
提示用户
↓
退出运行任务 / 保存状态
↓
安装
↓
启动
↓
Migration
↓
Health Check
```

存在运行中重型任务时，不强制立即升级。

## 11. 回滚

如果新版启动 Health Check 失败：

- 保留旧应用版本能力。
- 不自动回滚已成功完成且不可逆的 DB Migration。
- Breaking Migration 必须提前备份。

应用回滚和项目数据回滚是两个独立问题。

## 12. Release Channel

建议：

- nightly
- preview
- stable

AI 自动开发默认进入 PR / nightly，不直接发布 stable。

## 13. 发布质量门

Stable 前必须通过：

- Windows 安装测试
- macOS 安装测试
- Linux 启动测试
- 创建项目
- 打开旧项目
- Migration
- Worker 注册
- 基础 3D Viewer
- 至少一个真实 Fixture
- 导出 GLB

## 14. Release Notes

全部中文。

至少包含：

- 新功能
- 修复
- 兼容性变化
- 已知问题
- 数据迁移说明
- 模型 / Provider 变化

## 15. 依赖升级

框架 / Native dependency / AI model 升级不能混在无关功能 PR 中。

大版本升级单独提交并跑完整回归。

## 16. AI 开发规则

AI 不得因为“最新版更好”自动升级核心依赖。

升级必须有：

- 原因
- 影响范围
- 迁移说明
- Benchmark / Test
- 回滚路径
