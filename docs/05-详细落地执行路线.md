# 05 详细落地执行路线

## 1. 总原则

888 不采用“先把所有功能都做出来再一起调”的方式。

执行顺序必须满足：

```text
协议与状态
→ 最小可运行骨架
→ 真实观测
→ 几何求解
→ 世界模型
→ 跳跃空间关系
→ 重建
→ 生成补全
→ 验证闭环
→ 主动补拍
→ 编辑
→ 编译导出
→ 性能与稳定性
```

任何阶段没有通过验收，不进入依赖它的下一阶段。

---

# 阶段 0：冻结核心协议

## 目标

先确定“系统内部怎么说话”。

## 要做

定义：

- Observation Schema
- Evidence Schema
- Hypothesis Schema
- Zone Schema
- Anchor Schema
- Portal Schema
- Entity Schema
- GeometryRepresentation Schema
- Artifact Schema
- Candidate Schema
- Validation Result Schema
- Task Schema
- Provider Capability
- World Revision
- Compiler Target

以 `packages/schema/` 作为跨语言协议唯一权威来源。

第一阶段以 **JSON Schema Draft 2020-12** 定义权威 Schema，再通过 codegen 自动生成 Rust、TypeScript 与 Python 类型。任何语言都不得手工维护第二套同义正式结构。

## 产出

```text
packages/schema/
core/src/model/
workers/sdk/
ui/src/generated/
```

## 验收

- Rust / TypeScript / Python 读取同一 Fixture。
- 序列化结果一致。
- Schema Migration 测试存在。
- 不依赖任何具体 Provider。

## 目标

```text
│  └─ provider-sdk/

```

## 实现

### Desktop

Tauri + React + TypeScript。

完成：

- 创建项目
- 打开项目
- 项目列表
- Worker 状态
- 基础日志面板

### Core

Rust。

完成：

- SQLite 初始化
- Migration
- Artifact Store
- Command API
- IPC
- Job Engine 空骨架

### Worker

Python。

完成：

- 启动注册

# 阶段 2：观测导入系统

## 目标

所有真实输入先进入可信 Observation 层。

## 实现顺序

1. 图片导入。
2. Hash 去重。
3. EXIF。
4. Preview。
5. 质量检测。
6. 视频导入。
7. 视频关键帧。
8. 可选 GPS / 用户说明。

## UI

照片墙显示：

- 拍摄时间
- 分辨率
- 是否可用于几何
- 是否已分析
- 是否有 EXIF
- 所属 Cluster

## 验收

- 重复导入同一图片不重复存储。
- 原图永远不被后续任务修改。
- 删除 Observation 后派生依赖可以被识别。
- 1000 张图片导入不会造成 UI 冻结。

# 阶段 3：连续多图几何重建

## 目标

先解决技术最成熟的情况：有视觉重叠的一组照片。

## 实现

### 3.1 特征

- 全局 embedding
- 局部 keypoint

### 3.2 Pair Candidate

使用全局 embedding 与时间邻近筛选。

### 3.3 Matching

LightGlue / LoFTR 类匹配。

### 3.4 SfM

PyCOLMAP：

- Camera model
- Relative pose
- Incremental reconstruction
- Bundle Adjustment

### 3.5 输出

- Camera candidates
- Sparse points
- geometric Evidence

## UI

显示：

- 相机位置
- 相机视锥
- 稀疏点云
- 匹配关系

## 验收

标准房间数据集能够：

- 自动形成同一组件。
- 相机轨迹方向正确。
- 错误匹配被 RANSAC 大量过滤。
- 重启后求解结果可恢复。

# 阶段 5：空间结构与 Zone

## 目标

支持房间、室外、楼层等结构空间。

## 实现

1. 平面检测。
2. Floor / Wall 候选。
3. Door / Window / Stair 识别。
4. Observation Cluster。
5. Zone 候选。
6. Zone 局部坐标。
7. Zone 之间关系。

第一阶段允许用户人工确认 Zone 边界。

不要追求一次全自动。

## 验收

同一房间多图自动聚成同一 Zone。

明显不同房间不应被强行合并。

# 阶段 6：Anchor / Portal 与跳跃式照片

## 目标

这是 888 的第一次核心跃迁。

支持：

- 客厅左侧 + 厨房 + 客厅右侧
- 一楼 + 二楼
- 室内 + 室外
- 前院 + 后院

## 实现步骤

### 6.1 Anchor Detection

识别：

- 门
- 窗
- 楼梯
- 墙角
- 固定家具
- 外立面特征

### 6.2 Anchor Signature

组合：

- 视觉 embedding
- 语义
- 几何
- 颜色
- 位置关系

### 6.3 Semantic Spatial Matching

对未几何连通 Cluster 搜索候选 Anchor Match。

### 6.4 Hypothesis

每组不确定关系生成 Top-K 假设。

### 6.5 Constraint Solver

把 Anchor / Portal 关系加入 Factor Graph。

### 6.6 用户辅助

如果无法收敛：

UI 显示多个可能关系。

用户可选择：

- 确认
- 否决
- 暂不处理

## 验收

测试场景：

### A

客厅两侧照片之间没有直接重叠，但共享一张沙发 / 窗。

系统应建立候选关联。

### B

室内看到落地窗，室外看到同一窗。

系统应把两 Zone 通过同一 Anchor 建立关系。

### C

没有任何共同证据。

系统不得伪造 Verified Transform。

# 阶段 7：密集重建与混合表示

## 目标

真正生成高质量视觉世界。

## 实现

### 几何路径

```text
高重叠照片
→ MVS
→ Depth Fusion
→ Point Cloud
→ Mesh / Splat
```

### 两种并行输出

- Splat：快速高保真
- Mesh：编辑、物理、导出

两者都作为 Candidate。

## UI

允许切换：

- 原照片
- 点云
- Splat
- Mesh
- 深度
- Collider

## 验收

- Splat 可在 Viewer 稳定加载。
- Mesh 与相机位置一致。
- 世界状态不依赖某一种表示。
- 资产可独立失效并重算。

# 阶段 9：生成补全与 Provider Router

## 目标

补上真实观测恢复不了的部分。

## 先实现 Capability

- IMAGE_EDIT
- OBJECT_3D
- WORLD_COMPLETION
- TEXTURE

后续：

- AUDIO
- CHARACTER

## Provider

至少支持：

- 一个本地 / 开源路径
- 一个远程 Provider

## 关键

Provider 返回的是 Candidate。

不能直接更新世界。

## 验收

切换 Provider 后：

- World Schema 不变化。
- UI 不变化。
- 下游验证流程不变化。

# 阶段 10：室内外完整世界补全

## 目标

真正完成“一张室内 + 一张室外也能形成完整世界”。

## 实现

1. 室内 Zone 独立求解。
2. 室外 Zone 独立求解。
3. Anchor / Portal 匹配。
4. 多假设保留。
5. 已知部分固定。
6. 对中间缺失 Transition Zone 生成候选。
7. 明确标记 Generated。
8. 用户新增照片时重新求解并替换。

## 验收

室内和室外不需要共享直接像素重叠也能进入同一 World。

但系统必须区分：

- 确定连接
- 推断连接
- 生成连接

# 阶段 11：Render & Verify

## 目标

让系统第一次真正具备“自己判断做得对不对”的能力。

## 实现步骤

1. Offscreen Renderer。
2. 使用 Observation Camera 渲染。
3. 输出 RGB / Depth / Normal / IDs。
4. Evaluator。
5. Issue Localization。
6. Validation Record。

## 最先支持

- Camera error
- Position error
- Scale error
- Silhouette error
- Depth error

材质 / 光照后补。

## 验收

人工制造：

- 桌子向右移动 30cm
- 相机旋转 5°
- 模型扩大 20%

Evaluator 能正确分类大部分问题。

---

# 阶段 12：Repair Planner

## 目标

从发现错误进入自动修复。

## 实现

规则优先：

```text
位置错 → 调 Transform
尺度错 → 调 Scale
相机错 → 重新优化 Camera
局部几何错 → 局部 Replace
完全错误 → 重建 / 重新生成
```

每一次 Repair 都产生独立 Job。

## 验收

不允许出现：

“发现位置错 → 直接重新生成整张场景”

这种高成本行为。

---

# 阶段 13：Next Best View

## 目标

用户不知道拍什么时，由系统主动指导。

## 实现

1. 找低可信度区域。
2. 找多假设分歧区域。
3. 生成候选相机位。
4. 模拟这些观测可以看到哪些 Anchor。
5. 估算信息增益。
6. 排序。
7. 输出自然语言拍摄建议。

## 验收

室内外关系不确定时，系统优先建议“同时看到室内门框与室外建筑”的位置，而不是随便推荐拍更多照片。

# 里程碑定义

## M1：真实多图房间

连续照片可以重建出可进入空间。

## M2：跳跃多空间

不连续照片可以建立 Zone / Anchor / Portal 和多假设。

## M3：室内外世界

室内 + 室外可以形成统一世界，并明确区分已知 / 推断 / 生成区域。

## M4：自动质量闭环

系统可以自己发现位置、尺度、相机和几何问题并局部修复。

## M5：主动采集

系统可以推荐下一张最有价值的照片。

## M6：世界编译

同一 World State 可稳定输出至少 Web / GLB / Blender。

# 执行纪律

每个阶段必须遵守：

```text
实现
→ 单元测试
→ 固定测试数据
→ 集成测试
→ 实际样例
→ 失败样例
→ 修复
→ 回归
→ 达到验收
→ 进入下一阶段
```

不得以“接口已经写了”“模型已经调用成功”“能看到一个画面”作为阶段完成标准。

# AI 驱动执行附加规范

以上阶段路线保持不变，但每一个开发任务必须遵循统一 AI 执行路径。

## A. AI 开工前

1. 读取根目录 `AGENTS.md`。
2. 读取本任务对应的权威文档。
3. 检查当前代码与最近相关提交。
4. 明确任务影响模块。
5. 明确必须通过的测试和 Fixture。
6. 不重新研究已经被权威文档冻结的技术方向，除非现有方案已被事实证明失效。

## B. 标准执行闭环

    任务识别
    → 影响范围分析
    → 实现计划
    → 编码
    → 单元测试
    → 固定 Fixture
    → 集成测试
    → 自审
    → 独立 Review
    → 修复
    → 全量相关回归
    → PR / CI
    → 验证实际结果

“工具调用成功”“测试命令退出 0”“生成了文件”都不单独等于任务完成。

## C. AI 任务粒度

优先小而完整的垂直切片。

例如：

    图片导入
    → Asset 去重
    → Observation 创建
    → SQLite 持久化
    → UI 可见
    → 重启恢复
    → Fixture 通过

不要同时让一个普通任务修改 Schema、Job Engine、3D Viewer、Provider、Reconstruction、Exporter，除非这些改动共同构成不可拆的同一闭环。

## D. 固定开发命令

所有阶段最终统一收敛到：

    just setup
    just check
    just test-fast
    just test
    just test-world
    just benchmark

AI 不得在没有必要的情况下自行创造新的顶层执行方式。

## E. 阶段 0 增补

阶段 0 除冻结产品协议外，同时必须完成 AI 研发基础设施：

- 根目录 `AGENTS.md`
- `packages/schema` 单一真相源
- 类型生成器
- `justfile`
- 依赖边界检查
- 基础 CI
- Fixture 目录规范
- PR 验收模板
- 架构守卫脚本

这些基础设施完成后，才进入大规模 AI 并行开发。

## F. GTSAM 与算法实现顺序修订

第一阶段 GTSAM 放在 Python Solver / Vision Worker，不优先做 Rust FFI。

原因：与 PyCOLMAP、Open3D、PyTorch 共用数据处理链，AI 更容易在统一 Python 算法环境内调试，也能降低跨语言构建复杂度。

只有当算法稳定、性能数据证明必要时再下沉。

# 联想式能力实施插入点

联想能力不提前干扰基础几何重建。

## L1：在阶段 6 后加入基础联想

完成 Anchor / Portal 与跳跃照片基础能力后，加入：

- Associative Proposal Schema
- SAME_ENTITY_PRIOR
- SAME_ANCHOR_PRIOR
- SAME_ZONE_PRIOR
- PORTAL_PRIOR
- Proposal 去重 / Top-K

验收：联想只能创建 Proposal / Hypothesis，不能直接产生 Verified Relation。

## L2：在阶段 10 前加入空间拓扑联想

室内外补全前加入：

- Room / Zone topology prior
- Case Retrieval
- 缺失连接空间 Proposal

验收：无直接证据时允许生成多个连接候选，但不伪造精确 Transform。

## L3：与阶段 13 Next Best View 合并

Next Best View 升级为：

    联想
    → 找到最关键未决假设
    → 计算缺失证据
    → 推荐最有价值观测

验收：推荐视角必须能显著提高假设区分度。

## L4：后期再加入 VLM / LLM 世界常识

只有结构化 Prior / Hypothesis / Validation 链稳定后，才加入大模型世界常识推理。

避免早期让不可控自然语言推理成为架构核心。
