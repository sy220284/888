# Agent Note: 仓库自动化改为按需运行

Status: implemented

[English](2026-08-31-repository-automation-removal.md) | 中文

## Problem

仓库内的 GitHub Actions、Git 钩子和议题策略检查会自动执行验证或拦截仓库操作。这些自动化会产生维护成本，也限制仓库所有者自主选择检查时机。

## Decision

仓库不包含 GitHub Actions 工作流定义、Lefthook 配置与安装器，也不包含议题策略自动化。依赖安装不会修改 Git 配置，提交、合并和推送操作不会调用仓库提供的检查。

构建、测试、代码检查、文档检查、依赖检查和打包命令继续保留在 `package.json` 中，供本地显式调用。失效的 `check:ci:*` 入口和 Windows 门禁脚本已删除，其余本地检查组改由 `scripts/run-checks.ts` 执行。GitHub 仓库规则集为空，默认分支也没有保护规则或必需状态检查。

## Alternatives considered

**保留拉取请求检查，只提供提示。** 任何工作流触发器仍会消耗托管执行资源，也可能形成操作依赖，因此仓库不再保存工作流定义。

**只保留快速本地钩子。** 钩子仍会拦截提交、合并或推送，并且在检出内容变化后继续作为机器本地状态存在，因此安装过程不再配置钩子。

**保留文件并禁用工作流。** 禁用后的定义仍是陈旧自动化，也可能被意外重新启用；完整删除可以让仓库状态保持明确。

## Consequences

GitHub 和本地 Git 操作不会获得仓库提供的自动验证。贡献者与发布人员自行决定运行哪些手动命令，未经验证的改动可能直接进入默认分支。

旧版本曾在工作区之外写入钩子或 Git 配置，已有克隆可能继续保留这些机器本地状态，需要其所有者另行清理。
