# 888：证据驱动的渐进式世界重建与生成系统

> 从任意零散照片、视频与空间观测中，逐步理解、恢复、补全、验证并编译出一个可进入、可编辑、可交互、可导出的完整数字世界。

## 项目目标

888 不把“单张图片生成一个看起来像的 3D 场景”作为终点，而是把现实世界视为一个需要持续求解的对象。

系统允许输入：

- 单张照片
- 多张连续或跳跃式照片
- 室内与室外混合照片
- 不同房间、楼层、前院、后院等彼此不连续的空间照片
- 视频
- 深度、GPS、EXIF、用户文字说明等辅助观测

## 核心范式：证据优先世界编译器

888 的最终架构范式定义为 **Evidence-first World Compiler（证据优先世界编译器）**。

系统先保存观测、证据、约束与多个可能世界解释，再逐步收敛到 Canonical World State。生成模型只负责未知部分，不能替代真实证据。

质量闭环由三类能力共同组成：

```text
重建 / 生成器
      ↓
自动验收器
      ↓
局部修复器
      ↺
```

也就是之前确定的“生成 / 重建 + 裁判 + 修复”闭环。世界状态稳定后，再由 World Compiler 编译成不同平台需要的 Mesh、Splat、LOD、Collider、材质与资产格式。

系统会持续建立并修正统一世界状态：

```text
照片 / 视频 / 深度 / GPS / 用户说明
                  ↓
            观测理解引擎
                  ↓
        证据图 + 多假设图
                  ↓
          空间与约束求解
                  ↓
          规范世界状态
             ↙         ↘
        真实重建       生成补全
             \         /
              世界优化器
                  ↓
             渲染与验证
                  ↺
                  ↓
             世界编译器
      Web / Blender / Unity / Unreal / VR / AR
```

核心原则是：

1. **重建优先，生成兜底**：能从真实观测恢复的内容不重新“幻想”。
2. **证据优先，不确定性显式存在**：系统必须知道哪些是真实观测、哪些是推断、哪些只是暂时假设、哪些由 AI 补全。
3. **多假设并存，证据推动收敛**：信息不足时不强行选唯一答案。
4. **世界是持续演进的**：新增一张照片后，世界可以重新求解并替换旧的低可信补全。
5. **生成结果必须验收**：API 返回成功不等于世界正确。
6. **Agent 与底层模型都可替换**：Claude、Codex 只作为控制 / 开发入口；World Labs、Hunyuan、Meshy 等作为可插拔能力 Provider，任何一个都不成为系统核心。
7. **同一世界，多种输出**：同一份世界真相可以编译为不同平台和质量等级。

## 最终用户体验

理想体验应尽量简单：

```text
拖入若干照片 / 视频
        ↓
系统自动判断照片之间的空间关系
        ↓
先形成可进入的初步世界
        ↓
真实可确认部分优先重建
缺失区域自动补全
        ↓
系统标出低可信区域
并给出“下一张最值得拍哪里”
        ↓
用户可继续补拍，也可以直接使用
        ↓
新增观测自动替换低可信猜测
        ↓
世界不断变得更完整、更接近真实
        ↓
编辑 / 交互 / 导出
```

例如只有“一张客厅照片 + 一张建筑室外照片”，系统不会强行断言客厅位于建筑哪一侧，而是保留多种空间假设；如果后续补一张门口照片，系统再自动消除错误假设并收敛。

## 核心能力

- 单图快速世界生成
- 多图与视频渐进式重建
- 跳跃式照片空间关系求解
- 室内 / 室外 / 多楼层统一世界建模
- Zone / Anchor / Portal 分层空间模型
- 多假设世界状态
- 证据图与约束图
- 相机位姿、尺度与空间拓扑恢复
- Mesh / Gaussian Splat / NeRF / 纹理等混合表示
- 独立物体与角色重建
- AI 缺失区域补全
- 自动材质、光照、音频与物理生成
- 自动渲染回放与误差检测
- 局部修复与全局重新求解
- 下一最佳观测位置建议
- 任务队列、并行、失败重试、暂停恢复、成本控制
- Web / Blender / Unity / Unreal / Godot / VR / AR 导出
- 时间维度预留：同一地点不同时间的变化建模

## 技术总览

建议采用本地优先、模块化、多进程架构：

- **桌面壳与界面**：Tauri 2 + React + TypeScript
- **3D 编辑与预览**：Three.js + React Three Fiber + Rapier
- **核心编排与本地服务**：Rust
- **视觉 / 重建 / AI Worker**：Python
- **世界状态与任务元数据**：SQLite
- **大体积资产**：本地内容寻址文件存储
- **空间优化 / 因子图**：GTSAM（Python Worker）+ 888 自研约束抽象层
- **相机与几何重建**：COLMAP / PyCOLMAP + 可替换特征与匹配器
- **深度 / 分割 / 语义**：可替换视觉模型适配层
- **NeRF / Gaussian Splat**：gsplat 作为生产核心候选，Nerfstudio 用于实验 / 基线与可替换实现
- **网格处理**：Open3D / trimesh / Blender Headless
- **模型与服务接入**：Provider Router
- **工作流**：显式 Task Graph + Job Engine
- **质量闭环**：多指标 Evaluator + Repair Planner
- **导出**：glTF / GLB / USD / USDZ / FBX 等编译器

## 与原 Image Blaster 思路的关系

本方案保留其真正有价值的设计：

- 本地资产优先
- 生成历史不覆盖
- Provider 请求可追溯
- 静态环境与动态对象分离
- Three.js / Rapier 实时预览
- 能力拆分与 Provider 适配思想

但不继承以下核心约束：

- `.claude` 作为主架构
- Agent 记忆执行顺序
- 单图中心
- 固定脚本串行流程
- “一次生成成功即结束”
- 业务逻辑直接绑定具体模型
- 使用散落 JSON 文件承担完整世界数据库职责

888 的目标是让模型与 Agent 都成为可替换部件，而让**证据、约束、世界状态、验证闭环和世界编译**成为长期稳定的核心。

## 当前阶段

当前仓库首先建立完整设计与实施基线。后续开发严格按文档中的阶段、接口边界、验收门槛推进，避免先堆功能再返工核心架构。

## AI 驱动开发基线

888 按“AI 负责主要实现，人负责目标、决策与最终验收”的方式设计研发流程。

主技术栈保持不变：

- **界面与交互**：Tauri 2 + React + TypeScript
- **实时 3D**：Three.js + React Three Fiber + Rapier
- **核心状态与任务系统**：Rust
- **视觉 / 重建 / AI 算法**：Python
- **持久化**：SQLite + 本地内容寻址资产库

为了让 AI 可以长期持续推进而不造成架构漂移，研发侧增加以下强约束：

1. `AGENTS.md` 是所有 AI 开工前的第一入口。
2. 核心 Schema 只有一个权威来源，Rust / TypeScript / Python 类型全部自动生成。
3. 保持 Monorepo，不拆成大量微服务或多个仓库。
4. UI、Core、Worker、Provider、Compiler 之间使用固定依赖方向，并由自动检查守卫。
5. 统一开发工具链：前端 `pnpm`、Python `uv`、Rust `cargo`、跨语言统一入口 `just`。
6. AI 不能以“代码已写完”作为完成标准，必须通过测试、Fixture、回归和验收。
7. 所有真实缺陷都沉淀为长期回归用例。
8. 重型 GPU / 3D 测试可以进入阶段性或 Nightly 流程，基础边界和数据一致性测试必须进入每个 PR。

后续开发规范详见根目录 [AGENTS.md](AGENTS.md)。
